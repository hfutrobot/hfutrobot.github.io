Hexo 博客部署到云服务器完整指南

Hexo 博客部署到云服务器完整指南

📖 前言

在使用 Hexo 搭建博客后，除了部署到 GitHub Pages，我们还可以将博客部署到自己的云服务器上，这样可以获得更好的性能和自定义能力。本文将按照配置 SSH 密钥 → 配置部署路径 → 配置 GitHub Actions → 配置 Nginx 的顺序，详细介绍如何通过 GitHub Actions 自动将 Hexo 博客部署到云服务器。

🎯 部署方案

本文采用以下部署方案： - 本地：只推送到 GitHub 仓库 - GitHub Actions：自动构建并部署到云服务器 - GitHub Pages：可选，如果需要也可以同时部署到 GitHub Pages - 优势：无需在本地安装 rsync，Windows 系统也能轻松使用

第一步：配置 SSH 密钥

SSH 密钥用于 GitHub Actions 安全地连接服务器。我们在本地生成密钥对，然后将公钥添加到服务器，私钥添加到 GitHub Secrets。

1.4 将私钥添加到 GitHub Secrets

在本地查看私钥内容：

复制完整内容（包括 -----BEGIN OPENSSH PRIVATE KEY----- 和 -----END OPENSSH PRIVATE KEY-----）

添加到 GitHub Secrets：

  1. 进入 GitHub 仓库 → Settings → Secrets and variables → Actions
  2. 点击 New repository secret
  3. 创建以下 必需的 Secrets（部署到服务器）：
    • Name: SERVER_HOST，Value: 服务器地址（如 example.com 或 192.168.1.100）
    • Name: SERVER_USER，Value: www-data
    • Name: SERVER_DEPLOY_PATH，Value: 部署路径（如 /var/www/html）
    • Name: SERVER_PORT，Value: SSH 端口号（默认 22，如使用其他端口填写对应数字）
    • Name: SERVER_SSH_KEY，Value: 粘贴刚才复制的私钥内容（完整内容，包括 BEGIN 和 END 行）
  4. 可选的 Secret（如果需要部署到 GitHub Pages）：
    • Name: PERSONAL_TOKEN，Value: GitHub Personal Access Token（用于部署到 GitHub Pages）

问题 5：本地 hexo deploy 失败

原因： 本地只需要推送到 GitHub，不需要配置服务器部署。

解决方案： 确保 _config.yml 中只配置了 git 部署，不要配置 rsync。

📝 总结

通过以上四个步骤，我们完成了：

  1. ✅ 配置 SSH 密钥 - 在本地生成密钥，公钥添加到服务器，私钥添加到 GitHub Secrets
  2. ✅ 配置部署路径 - 在服务器上创建目录并设置权限
  3. ✅ 配置 GitHub Actions - 实现自动构建和部署
  4. ✅ 配置 Nginx - 让网站可以通过浏览器访问

现在你的 Hexo 博客可以： - 本地只需 hexo deploy 推送到 GitHub - GitHub Actions 自动部署到 GitHub Pages 和服务器 - Windows 系统无需安装 rsync，使用更方便
