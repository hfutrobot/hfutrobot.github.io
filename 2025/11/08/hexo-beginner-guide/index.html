Hexo 博客搭建完整指南：从安装到部署

📖 前言

Hexo 是一个快速、简洁且高效的博客框架，使用 Markdown 解析文章，可以在几秒内生成静态网页。本文将带你从零开始，完成 Hexo 博客的安装、主题配置，并通过 GitHub Actions 自动部署到 GitHub Pages。

🎯 本教程内容

  • 环境准备（Node.js、Git）
  • Hexo 安装与初始化
  • 主题安装与配置（以 Fluid 主题为例）
  • 创建两个 GitHub 仓库（源码仓库和 Pages 仓库）
  • 配置 GitHub Actions 自动部署
  • 创建第一篇文章并发布

🏗️ 部署架构

本教程采用双仓库 + GitHub Actions 的部署方案：

  • 源码仓库：存放 Hexo 源码（Markdown 文件、配置文件等）
  • Pages 仓库：存放编译后的静态文件（由 GitHub Actions 自动更新）
  • GitHub Actions：自动编译源码并部署到 Pages 仓库

优势： - 本地只需写代码和推送，无需手动编译部署 - 源码和生成文件分离，仓库更清晰 - 支持多设备协作，任何地方都能更新博客

第六步：创建 GitHub 仓库

我们需要创建两个仓库：

  1. 源码仓库：存放 Hexo 源码（如 my-blog）
  2. Pages 仓库：存放编译后的静态文件（如 your-username.github.io）

6.1 创建源码仓库

  1. 登录 GitHub
    • 访问：https://github.com
    • 如果没有账号，先注册
  2. 创建源码仓库
    • 点击右上角 “+” → “New repository”
    • 仓库名：my-blog（或你喜欢的名字）
    • 选择 Public 或 Private（都可以）
    • 不要勾选 “Initialize this repository with a README”
    • 点击 “Create repository”

6.2 创建 Pages 仓库

  1. 创建 Pages 仓库
    • 点击 “+” → “New repository”
    • 仓库名格式：your-username.github.io（必须与你的 GitHub 用户名一致）
    • 选择 Public（公开）
    • 不要勾选 “Initialize this repository with a README”
    • 点击 “Create repository”
  2. 配置 Pages 仓库
    • 进入刚创建的 Pages 仓库
    • 点击 Settings → Pages
    • Source 选择 Deploy from a branch
    • Branch 选择 main，文件夹选择 / (root)
    • 点击 “Save”

第七步：配置 GitHub Actions

7.1 生成 GitHub Personal Access Token

  1. 进入 GitHub 设置
    • 点击右上角头像 → Settings
    • 左侧菜单找到 Developer settings
    • 点击 Personal access tokens → Tokens (classic)
  2. 生成新 Token
    • 点击 Generate new token → Generate new token (classic)
    • Note：填写描述，如 “Hexo Deploy”
    • Expiration：选择过期时间（建议选择较长时间）
    • Select scopes：勾选 repo（全部权限）
    • 点击 Generate token
  3. 复制 Token
    • 重要：Token 只显示一次，请立即复制保存

7.2 配置 GitHub Secrets

  1. 进入源码仓库
    • 进入你创建的源码仓库（如 my-blog）
  2. 添加 Secret
    • 点击 Settings → Secrets and variables → Actions
    • 点击 New repository secret
    • 创建以下 Secret：
      • Name: PERSONAL_TOKEN
      • Value: 粘贴刚才生成的 Personal Access Token
      • 点击 “Add secret”

🔧 常见问题

问题 1：GitHub Actions 部署失败，提示 Token 无效

解决方案： - 检查 Personal Access Token 是否正确添加到 Secrets - 确认 Token 有 repo 权限 - 重新生成 Token 并更新 Secret

问题 2：访问 GitHub Pages 显示 404

解决方案： - 确认 Pages 仓库名格式正确：username.github.io - 等待几分钟，GitHub Pages 需要时间构建 - 检查 Pages 仓库 Settings → Pages，确认 Source 分支设置正确 - 检查 GitHub Actions 是否部署成功

问题 3：本地预览正常，部署后样式异常

解决方案： - 检查 _config.yml 中的 url 配置是否正确 - 确认使用的是 HTTPS 地址 - 清理缓存后重新部署：hexo clean，然后 push

问题 4：GitHub Actions 部署很慢

解决方案： - 这是正常现象，GitHub Actions 需要时间编译和部署 - 通常需要 1-3 分钟 - 可以在 Actions 页面查看实时日志

问题 5：修改主题配置后没有生效

解决方案： - 确认修改的是 _config.fluid.yml（主题配置）或 _config.yml（网站配置） - 推送代码后等待 GitHub Actions 重新部署 - 清除浏览器缓存后刷新
